# Сравнение промптов

Три формулировки лежат в `prompts.py`. После прогона пайплайн по умолчанию вызывает `plain`.

Общие пределы, их же проверяет `TextProcessingResult`:

- `summary` не длиннее 280 символов
- ровно 3 key points, каждый не длиннее 120 символов
- `response` не длиннее 200 символов

Варианты на одних и тех же текстах из `examples/sample_inputs.json`:

- `plain` — формулировка дня 1: «1–2 предложения» и «короткий ответ», без чисел. User-шаблон передаёт только текст.
- `limits` — те же поля JSON, числовые пределы записаны в system prompt. User-шаблон передаёт только текст.
- `checklist` — роль редактора и чеклист в system prompt. User-шаблон повторяет пределы рядом с текстом.

## Прогон

```bash
python compare_prompts.py
```

Команда пишет `output/prompt_comparison.json`. Для каждой пары вариант–текст там есть `ok`, длины `summary`, пунктов и `response`, сами поля ответа либо `error`.

## Лучший вариант

`plain`.

Прогон `compare_prompts.py` на пяти текстах дал 15 ответов из 15 валидных: у всех вариантов ровно 3 пункта, и ни один не вышел за пределы схемы. При равном числе успехов короче и ровнее оказался `plain`. Средняя длина summary — около 122 символов против 155 у `limits` и 198 у `checklist`. Средняя длина response — около 64 символов против 85 и 82. Числовые пределы в `limits` и `checklist` не добавили валидных ответов: модель писала длиннее и ближе к потолку. `plain` остаётся в лимитах без размазывания, поэтому он и выбран рабочим промптом.
