# sixth_task_nlp

Учебный LLM-пайплайн для обработки текста. День 1 принимает сырой текст и возвращает краткое содержание, три ключевые мысли и короткий полезный ответ. День 2 сравнивает три формулировки промпта с явными пределами длины. День 3 валидирует JSON со сводкой, категорией, тональностью, ключевыми мыслями и итоговым ответом. День 4 сначала определяет категорию и intent, затем кодом выбирает инструкцию ответа. День 5 проводит текст через пять шагов: смысл, классификация, сборка полей, ответ и проверка. День 6 повторяет временные сбои API, чинит плохой JSON одним запасным промптом и обрезает слишком длинный ответ.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В `.env` укажите `OPENAI_API_KEY`. Для совместимого API можно задать `OPENAI_BASE_URL` и `OPENAI_MODEL`.

## Запуск

Все примеры из `examples/sample_inputs.json`:

```bash
python main.py
```

Один произвольный текст:

```bash
python main.py --text "Как подготовиться к собеседованию на junior Python?"
```

Свой файл результата (по умолчанию `output/results.json`):

```bash
python main.py --output output/results.json
```

Пайплайн идёт по пяти шагам. `extract_meaning` читает только сырой текст. `classify` видит уже извлечённый смысл. `structured_fields` собирает из них один объект без нового вызова модели. `final_answer` берёт этот объект и инструкцию маршрута: жалоба получает эмпатичный ответ, продажа — короткий призыв, поддержка — шаги проверки. `self_check` сравнивает ответ с исходным текстом и отмечает противоречие или потерянную деталь. В консоли и в логе виден каждый шаг. В JSON сохраняются поля цепочки, `route`, `final_answer`, `delivery`, `consistent`, `details_kept`, `check_notes` и `warnings`.

Временная ошибка API (обрыв, таймаут, 408, 409, 429, 500, 502, 503, 504) и пустой ответ повторяются до трёх раз. Ответ 400 или 401 не повторяется. Невалидный JSON, пропущенное поле и слишком длинная строка один раз уходят в fallback-промпт; если строка после этого всё ещё длиннее уже заданного лимита, она обрезается. Если смысл или категория так и не собрались, у этого текста появляется короткое поле `error`, а остальные примеры идут дальше. Если сломался только ответ или проверка, результат всё равно сохраняется: ответ берётся из краткого содержания, а проверка помечается как невыполненная.

Негативные сценарии без ключа и без сети:

```bash
python check_failures.py
```

По умолчанию используется промпт `plain`. Другой вариант:

```bash
python main.py --prompt plain
python main.py --prompt checklist
```

Сравнение трёх формулировок на одних и тех же примерах:

```bash
python compare_prompts.py
```

Результат пишется в `output/prompt_comparison.json`. Какой вариант лучше, фиксируется в `prompt_comparison.md` после прогона с ключом.
